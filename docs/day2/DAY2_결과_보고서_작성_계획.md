# DAY2 결과 보고서 작성 계획

- 상태: 작성 계획 확정, 최종 보고서 본문 작성 전
- 최종 산출물 예정: `outputs/reports/day2/day2_result_report.md`
- 목적: 정해진 성능 목표 달성 여부만 주장하는 대신, EDA에서 시작해 Feature와 모델을 설계·비교·평가한 과정을 재현 가능한 근거와 함께 설명한다.

## 1. 작성 범위와 기준

제공된 결과 양식과 평가 기준을 보고서의 뼈대로 삼는다. DAY2 결과 양식은 문제와 데이터, EDA, 전략 연결, 모델 성능, 오류 분석, ESS 관점 해석, 참고자료 및 팀 정보를 요구한다. 평가 기준은 전략을 구현에 반영했는지(20점), Pipeline·데이터 분할·핵심 변수(40점), 성능 및 Gap 보고(20점), 도메인 관점 해석 및 한계(20점)를 본다.

보고서 작성 단계에서는 모델을 다시 학습하거나 Batch 2에 맞춰 모델·Feature를 조정하지 않는다. 현재 산출물에 저장된 결과를 검증해 보고하고, 실제 관찰과 해석을 구분한다. 프로젝트의 학습 목적에 맞춰 대안 비교와 선택 이유를 성능 숫자만큼 분명하게 적는다.

## 3. 성능 표에 넣을 확정 값

아래 값은 현재 저장된 평가 결과를 기준으로 하며, 최종 작성 직전에 원본 결과 파일과 다시 대조한다.

| 결과 양식 항목 | 값 | 정의 |
|---|---:|---|
| Train Batch 1 CV | 8.6168% (약 8.62%) | 개발 29개 셀의 5개 검증 Fold MAPE 평균 |
| Valid Batch 1 Holdout | 9.0802% (약 9.08%) | 고정 Holdout 7개 셀의 MAPE |
| Test Batch 2 | 25.6061% (약 25.61%) | Batch 2 평가 39개 셀의 MAPE |
| Gap Train–Valid | +0.4634 pp (약 +0.46 pp) | Valid MAPE − CV MAPE |
| Gap Valid–Test | +16.5259 pp (약 +16.53 pp) | Test MAPE − Valid MAPE |
| Gap Target–Test | +16.5061 pp (약 +16.51 pp) | Test MAPE − 9.1% 기준값 |

Batch 2의 보조 오차 지표는 MAE 129.2349 cycles, RMSE 153.0294 cycles다. 이들은 MAPE와 단위 및 의미가 다르므로 별도 열로 표시한다. Fold별 MAPE의 단순 평균과 모든 OOF 예측을 합쳐 계산한 pooled MAPE는 서로 다른 계산일 수 있으므로 혼용하지 않는다. 공식 결과 양식의 항목 이름은 유지하고, Gap의 부호와 계산 방향을 표 아래에 명시한다.

## 4. 포함할 시각 자료

보고서에는 모든 생성 그래프를 넣기보다 논지를 뒷받침하는 핵심 그림만 고른다.

1. Day1의 수명 또는 ΔQ 관련 EDA 그림 1개: Feature 후보의 출발점을 보여준다.
2. Feature/모델 비교 그림 1개: 비교 후 현재 접근을 택한 과정을 보여준다.
3. Batch 2 실제값 대 예측값 그림 1개: 외부 Batch에서의 성능과 편향을 보여준다.
4. 오류 분포 또는 잔차 그림 1개: 셀별 오차의 방향이나 크기를 보여준다.

각 그림에는 번호, 이해 가능한 제목, 축 단위, 한두 문장의 관찰을 붙인다. 실제 이미지 파일을 Markdown에서 표시하는 상대경로가 최종 위치에서 유효한지 확인한다. 세부 셀별 결과는 표를 과도하게 늘리기보다 예측 CSV를 연결한다.

## 5. 작성 중 확인할 사실과 주의점

- 논문 초록의 9.1%를 현재 프로젝트의 직접 재현 결과라고 표현하지 않는다. 데이터 날짜·분할·모델·Target 처리 조건이 다르며, 원 논문 표의 단일 분산 모델 결과(주 테스트 14.7%, 보조 테스트 11.4%)와 초록의 최선 결과는 구분한다.
- 현재 보고 대상은 LinearRegression을 사용한 현재 실험이다. Elastic Net이나 Ridge로 이미 학습했다고 쓰지 않는다. Ridge와 부스팅은 비교 후보로 설명한다.
- 회귀 문제이므로 Accuracy, F1-score 같은 분류 지표를 회귀 성능처럼 제시하지 않는다. MAPE와 cycles 단위 MAE/RMSE를 사용한다.
- 관찰된 프로토콜 차이와 예측 오류의 동시 발생을 인과관계로 단정하지 않는다.
- 실제 실험 성능이 목표보다 낮더라도 결과를 숨기거나 Batch 2에 맞춰 재조정하지 않는다. 성능 Gap과 학습 내용을 투명하게 설명한다.
- 제출 양식에서 요구하는 팀원/역할 및 공개 저장소 URL은 현재 자료만으로 확인되지 않았다. 최종 보고서에 임의로 만들어 넣지 말고, 제출 전에 실제 정보로 채울 항목으로 표시한다.

## 6. 작성 및 검토 순서

1. 데이터 분할, 선택 모델, 예측 CSV 및 이미지의 파일 위치를 확인한다.
2. 표의 수치와 Gap 방향을 평가 결과 파일에서 다시 대조한다.
3. 위 목차 순서대로 본문을 작성하고, 먼저 관찰 사실을 쓴 다음 해석을 분리한다.
4. 각 평가 항목에 대응하는 보고서 절과 근거가 실제로 있는지 확인한다.
5. Markdown 링크와 이미지가 렌더링되는지, 용어가 앞뒤에서 일관되는지 확인한다.
6. 결과 양식의 팀/URL 등 미확인 정보를 표시하고, 근거 없는 주장이 없는지 최종 검토한다.

완료 기준은 평가 기준 네 영역 모두에 대응하는 근거가 보고서에 있고, 숫자와 Gap을 재현할 수 있으며, 데이터 범위·모델 선택·오류 해석의 한계가 과장 없이 설명되고, 링크된 그림·파일을 열 수 있는 것이다.
