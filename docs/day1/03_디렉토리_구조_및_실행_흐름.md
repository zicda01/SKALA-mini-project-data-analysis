## 4. 실행 흐름

아래 노트북 이름과 함수 이름은 구현 제안이며, 현재 구현된 파일을 의미하지 않는다. 노트북은 필요한 단계마다 추가한다.

### 1단계. 환경과 데이터 확인

프로젝트 `.venv`를 노트북 커널로 사용한다. `requirements.txt`에는 실제 사용하는 의존성을 기록한다. 노트북 실행에는 `ipykernel`과 선택한 실행 도구(JupyterLab 등)가 필요하다. Parquet 캐시를 사용하면 `pyarrow` 등 엔진도 추가한다. 로더를 `h5py`로 구현하면 Scratch의 `mat73` 의존성을 그대로 가져올 필요는 없다.

세 원본이 이미 있으면 다시 다운로드하지 않는다. 누락된 데이터는 프로젝트 루트에서 다음 명령으로 받는다.

```bash
python src/download_data.py
```

### 2단계. 데이터 구조 탐색

`00_data_inspection.ipynb`에서 Batch 1의 셀 메타데이터와 summary를 확인한다. 같은 로더를 Batch 2·3에 적용해 구조 차이를 확인한다. 모든 cycle 원시 시계열을 한꺼번에 읽지 않는다.

### 3단계. 질문별 EDA

`01_batch_eda.ipynb` 상단에서 Batch, 초기 cycle 범위, 수명 그룹 기준, 대표 셀, 그래프 표시 범위를 설정한다. 공통 모듈을 호출해 결과를 확인하고 조건을 바꾸어 추가 탐색한다. 먼저 Batch 1에서 검증한 뒤 같은 조건을 Batch 2·3에 적용한다.

Batch별 노트북을 복사하는 대신 Batch 설정을 바꾸어 같은 분석 셀을 사용한다. 비교에 사용할 표와 선택한 그래프를 저장할 때 Batch와 분석 조건을 기록한다.

### 4단계. 비교와 정리

`02_batch_comparison.ipynb`에서 같은 조건으로 생성한 결과를 비교하고 Feature 후보를 검토한다. 검증된 관찰을 충분히 쌓은 후 최종 보고서로 옮긴다.

### 노트북 실행 기준

- 개인 PC 경로 대신 프로젝트 루트를 기준으로 데이터와 모듈 경로를 설정한다. 작업 디렉토리가 프로젝트 루트인지 `notebooks/`인지 명시적으로 확인한다.
- 공통 모듈 수정 후 재로딩하거나 커널을 재시작하여 변경을 반영한다.
- 중요한 분석은 커널 재시작 후 위에서부터 전체 실행하여 재현성을 확인한다.
- 관찰에는 사용한 Batch·셀·cycle 범위·필터 조건을 함께 기록한다.
- 노트북 실행만으로 전체 모델 학습이나 보고서 생성을 수행하지 않는다.

## 7. Scratch Notebook의 역할

Scratch Notebook은 다음 용도로 유지한다.

- 데이터 구조 이해
- 예시 EDA 확인
- 변수 의미 확인
- ΔQ(V) 계산 방향 참고

Scratch 원본은 `provided-references/`에 보존한다. 새 탐색 노트북은 `notebooks/`에 작성하고, 반복되는 분석 로직은 `.py` 모듈로 분리한다.

Scratch의 개인 경로, cycle 번호 생성 방식, EOL 기준선, 셀 순서에 따른 색상과 수명 해석, 인과적 표현은 그대로 복사하지 않는다. 실제 데이터와 코드로 검증한 내용을 사용한다.
