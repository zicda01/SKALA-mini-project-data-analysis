# ESS Battery Health — 작업 가이드

## 현재 목표와 진행 방식

직접 데이터를 분석할 수 있는 아키텍처를 만들고, 노트북에서 그래프와 표를 확인하며 실질적인 EDA를 수행한다. 관찰에서 가설과 추가 분석 아이디어를 얻고, 검증한 내용을 최종 보고서에 반영한다.

보고서는 분석 결과가 축적된 이후 작성한다. 초기 단계에서는 분석 환경과 반복 탐색 가능한 구조를 먼저 마련한다.

```text
환경 / 데이터 구조 확인
→ 공통 로딩·전처리 + 탐색 노트북
→ 그래프·표 확인
→ 관찰 / 가설 기록
→ 조건을 바꾸어 추가 분석
→ 세 Batch에 같은 기준 적용
→ Feature 및 모델 전략 검토
→ 보고서 반영
```

## 작업 공간

- `src/`: 공통 로딩·전처리·계산·시각화 함수.
- `notebooks/`: 함수 호출, 그래프·표 확인, 조건 변경 실험, 관찰과 질문 기록.
- `provided-references/`: 원본 Scratch와 과제 요구사항.
- `data/processed/`: 재사용할 가공 데이터와 캐시.
- `outputs/`: 선택한 그래프와 최종 보고서.

탐색 코드는 노트북에서 시작할 수 있다. 반복되거나 검증된 로직은 공통 함수로 옮긴다. 모든 실험을 처음부터 모듈로 만들 필요는 없다.

## 첫 번째 구현 목표

Batch 1의 메타데이터와 summary를 공통 로더로 읽고, 첫 노트북에서 셀 정보·cycle 번호·결측 현황과 간단한 수명 분포를 직접 확인한다. 커널 재시작 후 전체 실행이 가능하면 첫 단계가 완료된다.

이후 동일 로더를 Batch 2·3에서 검증하고, 열화 곡선과 초기 신호 탐색을 점진적으로 확장한다.

## 핵심 원칙

동일한 분석 기준을 세 Batch에 적용하고 Batch 구분을 유지한다. 실제 실행 결과로만 관찰을 작성하며, 상관관계를 인과관계로 표현하지 않는다. 모델과 Feature는 EDA 이후 결정한다.

공통 로더 `src/load_data.py`와 첫 노트북 `notebooks/00_data_inspection.ipynb`를 작성했다. 원본 cycle 번호와 summary 값을 유지하며, 메타데이터·summary와 요청한 상세 곡선만 읽는다. 세 Batch의 모든 summary 값이 원본과 일치함을 확인했다.
