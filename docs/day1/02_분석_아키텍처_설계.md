# 분석 아키텍처 설계

## 1. 설계 원칙

이번 프로젝트의 핵심은 **Batch별 코드를 따로 만드는 것이 아니라 하나의 공통 분석 파이프라인을 세 Batch에 반복 적용하는 것**이다.

잘못된 구조:

```text
analyze_batch1.py
analyze_batch2.py
analyze_batch3.py
```

권장 구조:

```text
공통 함수
    ↓
Batch 1
Batch 2
Batch 3
```

예:

```python
analyze_batch(batch, batch_name)
```

## 2. 노트북 중심 탐색 구조

`src/`는 공통 로직을 제공하고 `notebooks/`는 사용자가 결과를 확인하는 중심 작업 공간이 된다.

| 계층 | 책임 |
|---|---|
| 로더 | 메타데이터·summary·요청한 cycle 곡선을 선택적으로 읽기 |
| 전처리 | 원본 cycle 번호를 유지한 표와 품질 점검 결과 생성 |
| 분석 / 시각화 | 입력 표와 분석 조건으로 통계·Feature·Figure 생성 |
| 노트북 | 조건 설정, 함수 호출, 출력 확인, 추가 실험과 관찰 기록 |
| 산출물 | 검증된 그래프·표를 저장하고 이후 보고서에서 참조 |

노트북에서 만든 일회성 실험은 탐색 중 유지할 수 있다. 여러 Batch에서 재사용하거나 검증이 필요한 계산은 공통 모듈로 옮긴다. 시각화 함수는 Figure/Axes를 반환하여 노트북에서 표시·수정하고 필요할 때 저장한다. 분석 함수가 보고서를 자동 작성할 필요는 없다.

### 데이터 접근과 메모리

세 원본 파일은 합계 약 7.7 GiB이며, Python 객체로 전체 변환하면 메모리 사용이 더 커질 수 있다. `h5py`를 이용한 선택적 접근을 우선 검토한다. 먼저 셀 메타데이터와 summary만 읽고, ΔQ(V) 또는 전류 분석에 필요한 셀·cycle·필드만 요청한다.

HDF5 파일 핸들은 명시적으로 닫는다. 캐시는 원본 파일 정보, 처리 버전, 분석 조건을 함께 기록하여 오래된 결과를 구분한다. 캐시를 사용할 때도 원본 cycle 번호와 셀 식별자는 보존한다.

## 4. 데이터 분석 단위

### 4.1 Cycle-level

한 행이 한 셀의 한 cycle을 의미한다.

예상 컬럼:

```text
batch
cell_id
cycle
cycle_life
charging_policy
QD
QC
IR
Tavg
Tmax
Tmin
chargetime
```

사용 목적:

- Qd 열화 곡선
- IR 변화
- 온도 변화
- 충전 시간 변화
- 초기 cycle 통계량 계산

---

### 4.2 Cell-level

한 행이 하나의 배터리 셀을 의미한다.

예상 Feature:

```text
batch
cell_id
cycle_life
charging_policy

mean_QD_early
std_QD_early
delta_QD
QD_slope

mean_IR_early
delta_IR
IR_slope

mean_Tavg
mean_Tmax

mean_chargetime

deltaQ_mean
deltaQ_var
deltaQ_min
deltaQ_max
```

모델링 전략은 최종적으로 이 Cell-level Feature Table을 기준으로 수립한다.

## 5. 각 모듈의 역할

### `download_data.py`

Kaggle에서 지정한 Batch 파일을 다운로드한다.

```text
Kaggle
→ data/raw/
```

### `load_data.py`

MATLAB `.mat` 파일을 Python 구조로 로드한다.

역할:

- MATLAB v7.3 대응
- Batch Object 생성
- Cell 구조 정규화

### `preprocess.py`

중첩된 데이터에서 분석 가능한 DataFrame을 생성한다.

역할:

- summary 추출
- cycle-level 데이터 생성
- batch name 부여
- cell_id 관리

### `eda.py`

5개 과제 질문 중 기본 EDA를 처리한다.

역할:

- Cycle Life 분포
- 열화 곡선
- C-rate / policy 분석
- 주요 통계량

### `delta_q_analysis.py`

ΔQ(V) 전용 분석 모듈.

역할:

```text
cycle 10 Qdlin
cycle 100 Qdlin
→ ΔQ(V)
→ 통계 Feature
```

### `feature_analysis.py`

초기 cycle Feature와 Cycle Life의 관계를 분석한다.

역할:

- 상관관계
- Feature Ranking
- Multicollinearity 확인
- 모델 후보 Feature 정리

### `compare_batches.py`

Batch 간 분석 결과를 비교한다.

역할:

```text
Batch 1
Batch 2
Batch 3
→ 공통점
→ 차이점
→ 일반화 가능한 Feature 판단
```

## 6. 분석 설계에서 중요한 점

### Batch별 Cell ID는 독립적으로 관리

`cell_id=0`이 Batch 1과 Batch 2에서 동시에 존재할 수 있으므로 다음 조합을 식별자로 사용한다.

```text
(batch, cell_id)
```

### 전체 Batch를 단순 concat해서 끝내지 않는다

이번 과제는 Batch 간 차이를 비교하는 것이 목적이므로 Batch 구분 컬럼을 반드시 유지한다.

### EDA 결과는 공통 포맷으로 저장

예:

```text
outputs/
├── figures/
│   ├── batch1/
│   ├── batch2/
│   ├── batch3/
│   └── comparison/
```

이 구조를 사용하면 Batch별 결과와 비교 결과가 혼재하지 않는다.

## 7. 최종 분석 아키텍처

```text
                  ┌─ Batch 1
Raw Loader ───────┼─ Batch 2
                  └─ Batch 3
                       ↓
                Common Preprocess
                       ↓
                Common EDA Logic
                       ↓
                 Batch Results
                       ↓
                Batch Comparison
                       ↓
              Feature Engineering
                       ↓
                Model Strategy
```

이 구조의 목적은 **세 Batch에 동일한 분석 기준을 적용해 비교 가능성을 확보하는 것**이다.
