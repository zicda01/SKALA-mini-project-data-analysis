# DAY2 학습 전 데이터 점검

작성일: 2026-10-02 · 대상: 과제의 Batch 1·2·3 원본 파일

## 1. 결론과 다음 작업에 미치는 영향

실제 barcode를 복원해 대소문자 통일 후 비교한 결과, 세 batch 간 같은 barcode는 없었다. 다만 수명 라벨의 관측 근거가 batch마다 다르며, Batch 1의 10개 셀은 기록 종료 당시 용량이 EOL 참조값보다 상당히 높았다. 이 항목을 완전한 EOL 수명 정답으로 무조건 사용하는 것은 부적절할 수 있다. Batch 1에서 프로토콜을 그룹으로 유지한 Hold-out과 5-fold CV는 구성 가능하다.

이번 단계는 점검 코드와 표를 생성했으며 모델을 학습하지 않았다. 원본·DAY1 특징·수명 라벨은 수정하지 않았다. 46개 전체를 사용한 분할은 구현 가능성을 확인한 예비안이며, 확정 학습 집합이 아니다.

## 2. 원본 파일과 원논문 코드의 범위

| 프로젝트 batch | 파일 내부 batch_date | 항목 수 | 유효 수명 라벨 |
|---|---|---:|---:|
| Batch 1 | 2017-05-12 | 46 | 46 |
| Batch 2 | 2018-02-20 | 47 | 39 |
| Batch 3 | 2018-04-12 | 46 | 44 |

파일명과 내부 날짜가 일치한다. 반면 원저자 저장소의 [Batch 2 로딩 코드](https://github.com/rdbraatz/data-driven-prediction-of-battery-cycle-life-before-capacity-degradation/blob/master/BuildPkl_Batch2.ipynb)는 **2017-06-30** 파일을 사용한다. 현재 과제의 2018-02-20 Batch 2와 동일한 데이터라고 가정할 수 없다.

원저자의 [데이터 통합 코드](https://github.com/rdbraatz/data-driven-prediction-of-battery-cycle-life-before-capacity-degradation/blob/master/Load%20Data.ipynb)는 Batch 1 일부 기록의 연장 병합, EOL 미도달 항목 제외, Batch 3 잡음 항목 제외를 수행한다. 그 코드는 당시 Batch 1/2/3에서 최종 41/43/40개를 사용한다. 현재 과제의 batch 구성이 다르므로 이 수와 제외·병합 인덱스를 일괄 적용하지 않는다. 특히 현재 Batch 2에서 원논문의 연장 셀 인덱스를 삭제하거나 Batch 1 수명에 임의 상수를 더하지 않는다.

따라서 DAY2의 9.1%는 과제에서 지정한 비교 목표이며, 해당 목표와의 Gap은 동일 데이터·분할의 논문 재현 오차라고 표현하지 않는다.

## 3. 물리 셀 식별 점검

### 3.1 내부 객체 값과 실제 barcode의 차이

기존 로더가 보존하는 `barcode_raw`·`channel_id_raw`는 `MATLAB_class=string`인 uint32 객체 핸들이다. 예를 들어 Batch 1 cell 0과 Batch 2 cell 0의 barcode 핸들은 같지만, 실제 문자열은 다르다.

| 항목 | Batch 1 cell 0 | Batch 2 cell 0 |
|---|---|---|
| 내부 barcode 핸들 | 같은 6개 uint32 값 | 같은 6개 uint32 값 |
| 복원한 barcode | EL150800460514 | EL150800737291 |
| 복원한 channel | 1 | 10 |

점검 코드에서 `#subsystem#/MCOS` 참조와 UTF-16LE 문자열 저장부를 따라 실제 문자열을 복원했다. 객체·문자열 헤더와 길이를 검사하고 barcode의 `EL`+12자리 형식과 channel의 숫자 형식을 확인했다. 이 디코더는 세 파일에서 관찰한 스칼라 문자열 구조에 한정한다. 다른 MATLAB 객체 구조를 일반적으로 지원한다고 주장하지 않는다.

### 3.2 중복 결과

- 각 batch 내부 barcode는 모두 고유했다.
- barcode를 대문자로 정규화했을 때 Batch 1–2, 1–3, 2–3 교집합은 각각 **0개**다.
- 초기 cycle 10–100의 cycle·QD·QC·IR·온도·충전 시간 원본 배열이 완전히 같은 batch 간 항목도 **0개**다. 완전 일치 비교는 복사 기록 탐지의 보조 근거이며 물리 셀 식별을 대신하지 않는다.
- channel은 실험 장비 위치로서 재사용될 수 있으므로 물리 셀 ID로 사용하지 않는다.

**판단:** 제공 파일의 barcode 기준으로 학습·테스트 간 동일 셀 중복의 증거는 없다. 기록되지 않은 재라벨링까지 없음을 보장하는 것은 아니다. 다음 단계의 물리 셀 관리 키는 복원한 barcode를 사용한다.

## 4. 수명 정의와 기록 길이

### 4.1 점검 방법

0 이하·비유한 QD는 EOL crossing에서 제외했다. 기존 용량 기준값 1.1 Ah의 80%인 **0.88 Ah 이하가 처음 관측되는 cycle**을 진단값으로 계산했다. 개별 셀 cycle 2 용량의 80% crossing도 별도로 저장했다. 이 두 진단값을 `cycle_life`로 덮어쓰지 않는다.

| 구분 | Batch 1 | Batch 2 | Batch 3 |
|---|---:|---:|---:|
| 유효 수명 라벨 | 46 | 39 | 44 |
| 마지막 cycle = 라벨 − 1 | 46 | 0 | 44 |
| 라벨 이후 관측이 있는 항목 | 0 | 39 | 0 |
| 라벨 = 최초 QD≤0.88 회차 | 0 | 39 | 0 |
| 유효 라벨 중 관측 QD≤0.88 없음 | 46 | 0 | 44 |
| 유효 라벨 중 마지막 QD>0.90 | 10 | 0 | 0 |

Batch 2의 유효 라벨 39개는 모두 최초 QD≤0.88 회차와 정확히 일치한다. 이후에도 15–66회 관측이 있으므로 전체 기록 길이는 수명 라벨과 다르다. 이런 기록이 있다는 사실만으로 연장된 동일 셀이나 잘못된 라벨로 판단하지 않는다. 초기 100회 입력만 사용하는 원칙을 유지한다.

Batch 1·3은 라벨이 마지막 관측 다음 회차다. 원본에 라벨 회차의 QD가 없으므로 EOL 도달을 직접 확인할 수 없다. 다만 Batch 1의 아래 10개를 제외한 36개는 마지막 QD가 0.8800565–0.88336319 Ah이고, Batch 3의 유효 44개는 0.88000458–0.88167018 Ah여서 0.88 경계에 가깝다. 이들은 끝점 인근 라벨이라는 관측과 부합하지만, 다음 회차의 실제 측정값을 복원한 것은 아니다.

### 4.2 Batch 1의 수명 정답 검토 대상 10개

| cell_id | 저장된 cycle_life | 마지막 QD (Ah) | 원저자 코드의 관련 처리 |
|---:|---:|---:|---|
| 0 | 1190 | 1.026210 | 다른 Batch 2 파일의 연장 기록 병합 대상 |
| 1 | 1179 | 1.038225 | 동일 |
| 2 | 1177 | 1.043279 | 동일 |
| 3 | 1226 | 0.970921 | 동일 |
| 4 | 1227 | 1.021960 | 동일 |
| 8 | 879 | 0.969025 | 80% 용량 미도달 제외 대상 |
| 10 | 906 | 0.961019 | 동일 |
| 12 | 902 | 0.913119 | 동일 |
| 13 | 897 | 0.923136 | 동일 |
| 22 | 891 | 0.963279 | 동일 |

원저자 처리 근거는 위 데이터 통합 코드다. 현재 로컬 Batch 1의 날짜·파일명·cell 위치와 끝점 관측이 이 처리 내용에 부합한다. 그러나 현재 과제의 Batch 2는 다른 날짜이므로 연장 기록이 있다고 가정해 병합할 수 없다.

**해석:** 이 10개는 측정값 오류로 확정한 이상치가 아니라, 완전한 수명 라벨로 사용하기 어려운 기록 중단·연장 후보다. `마지막 QD>0.90`은 확인용 표시이며 보편적인 EOL 임계값이나 자동 제외 기준이 아니다. Batch 1 전체에서 crossing이 관측되지 않았다는 이유로 46개 모두를 검열 데이터로 단정하지 않는다.

**후속 학습 권고:** 이 10개를 정답 불확실성 사유로 기본 회귀 학습 집합에서 제외하는 36개 구성을 우선 정리하고, 저장된 라벨 그대로 46개를 사용하는 구성은 민감도 비교로 구분한다. 기본 구성 선택은 위 라벨 근거로 정하며 Batch 2의 예측 오차를 보고 선택하지 않는다. 정확한 총수명을 복원하려면 원래 연장 파일과 대응 근거가 필요하며, 이번 점검에서 복원하지 않았다.

수명 누락 항목은 Batch 2의 `22, 23, 35, 36, 37, 38, 39, 40`, Batch 3의 `23, 32`다. 누락 라벨을 0이나 기록 길이로 채우지 않는다. 현재 유효 테스트 라벨은 Batch 2 39개를 유지할 수 있다.

## 5. 충전 프로토콜과 분할 가능성

프로토콜 키는 공백만 제거한다. `newstructure`·`SLOWCYCLE` 등을 삭제하거나 C-rate가 비슷한 정책을 임의로 합치지 않는다.

| 구분 | Batch 1 | Batch 2 | Batch 3 |
|---|---:|---:|---:|
| 전체 정책 종류 | 23 | 20 | 8 |
| 유효 라벨 항목의 정책 종류 | 23 | 12 | 8 |
| 유효 라벨 정책당 항목 수 | 1–3 | 2–6 | 2–8 |

Batch 1·2의 공통 정책은 `4.8C(80%)-4.8C`, `6C(60%)-3C` 두 가지다. 서로 다른 셀이 동일 정책으로 실험됐다는 사실만으로 타깃 누수라고 단정하지 않는다. 다만 Batch 1 내부 검증에서는 과제의 취지를 반영해 정책 그룹을 분리한다. batch 간 서로 다른 정책 분포도 일반화 차이의 배경으로 기록한다.

### 5.1 46개 기준 예비 분할

`GroupShuffleSplit(test_size=0.2, random_state=42)`를 사용한다. 20%는 그룹 비율이며 셀 비율이 정확히 20%가 되는 것은 아니다.

| 구분 | 셀 수 | 정책 수 |
|---|---:|---:|
| 개발 집합 | 35 | 18 |
| Hold-out | 11 | 5 |

개발 집합의 GroupKFold 5-fold에서 학습/검증 셀 수는 27/8, 27/8, 28/7, 29/6, 29/6이다. Hold-out–개발 및 모든 CV fold 학습–검증의 프로토콜 교집합이 0임을 assert로 확인했다. 이 단계는 모델을 적합하거나 MAPE를 계산하지 않았다.

### 5.2 권고 구성의 영향

Batch 1 검토 대상 10개를 제외하면 **36개·20개 프로토콜**이다. 같은 seed와 그룹 Hold-out 비율로 개발 29개·16개 프로토콜, Hold-out 7개·4개 프로토콜로 나뉘는 것을 확인했다. 정확한 셀 목록과 CV 분할은 학습 테이블을 구성하는 다음 단계에서 확정·저장한다. 이전 DAY1의 83–90개 학습 가정은 DAY2에 적용되지 않으며, 이 규모에서는 단순 후보와 제한된 탐색의 필요성이 더 커진다.
